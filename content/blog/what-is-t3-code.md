## What is T3 Code?

T3 Code is a desktop, web, and mobile control surface for coding agents already installed on a machine. The [homepage](https://t3.codes/), read November 8, says “the open-source control plane for coding agents” and “bring your own subscription.” The [README](https://github.com/pingdotgg/t3code/blob/main/README.md) says it “enables control of the agents on your machine” from an iOS app, an Android app, a [web app](https://app.t3.codes), and an Electron desktop app. The repository homepage field points at t3.codes. The MIT license file on main is copyright 2026 T3 Tools Inc.

It is not a new coding model. The FAQ’s cost answer says you bring your own subscription and still pay your provider. The homepage says T3 Code does not resell tokens. You plug in credentials you already have, and the app orchestrates those agents.

The repository was created February 8, 2026. On the November 8 snapshot, `pushed_at` was 03:41:34 UTC, a few minutes before that morning’s star count. On the November 10 snapshot it was 2026-11-10T11:47:46Z. The default branch is `main`. The primary language field was TypeScript on both reads.

## Is T3 Code a harness?

The FAQ answers that question with no. Read November 8, the “Is T3 Code a harness?” section says a harness is what turns an LLM into an agent: it gives the model tools, a way to call them, runs them, and hands the results back. It names Claude Code as an interface plus a harness underneath, the Anthropic Agent SDK, and Codex as the app plus the Codex App Server. The next sentence is the definition that matters here: T3 Code uses those harnesses. It is not a harness, and it does not work without one.

The same answer uses a kitchen line. The model is the chef. The harness is the kitchen. T3 Code is the restaurant that lets you bring whatever kitchen you want. That matches the definition on this site. A [harness](/glossary/harness) is the runtime around a model: the loop, the [tools](/glossary/tool-use), the memory, the permissions, and the stop conditions. [What is an AI agent harness?](/blog/what-is-an-ai-agent-harness) is the longer guide. T3 Code sits outside that runtime and drives it.

The homepage does not use the FAQ’s wording. Its testimonials, on the same page the same morning, include the line “Since I've started using T3 Code I no longer care which harness is used,” and another that calls T3 Code “the one AI harness.” Those are quotes the homepage prints. They are not the FAQ’s definition. The FAQ is the project’s own answer to the question, and the answer is no.

## How much does T3 Code cost?

The FAQ’s answer is nothing. The heading “How much does T3 Code cost?” says there is no way to pay the project to use T3 Code. You bring your own subscription. It is free and open source (MIT). You still pay your provider the way you already do. The README’s version of the same point is the heading “Wait, what are you selling me?” and the answer “Nothing.”

T3 Connect, the built-in remote link, is a separate sentence. The FAQ says it is free too, for now. Every account can connect up to 3 machines running T3 Code. Phones and browsers that connect to them do not count. Need more machines, and the FAQ says to link a paid T3 Chat account. Pro raises the cap to 10 machines. Premier raises it to 100. The free T3 Chat plan keeps the normal limit of 3. The FAQ does not print a dollar price for Pro or Premier, and this page does not add one.

The same answer includes the hedge worth quoting: “We don't want to charge for this, but if the bill gets unacceptable we may have to change course.” The alternatives it names are forking the project, self-hosting, or using Tailscale. The remote-access doc repeats the 3, 10, and 100 machine caps and does not repeat the words “for now.”

What you still pay is the agent subscription. [Claude Code vs Codex pricing](/blog/claude-code-vs-codex-pricing) is the dated comparison of those plans. This page does not restate those prices. The FAQ also says T3 Code can take an API key or an OpenRouter endpoint on a separate provider instance, so a subscription is the default path, not the only one the docs describe.

## How does remote and mobile control work?

The agents run where T3 Code runs: a desktop, a server, or a VPS. You connect to that machine from somewhere else. The FAQ says less than 5 percent of that author’s prompts run on a laptop, and that `npx t3 up` on the machine is the remote path they use. The phone does not become the computer. The FAQ’s mobile answer says the iOS or Android app connects to your computer with T3 Connect or a pairing link, the phone is a remote, and the computer does the work and needs to stay on.

The remote-access page, read the same morning, names three ways onto the host. T3 Connect is the account link: sign in on the host, enable it, and pick that environment on the other device. `t3 up` asks whether other devices should use T3 Connect, the local network, or both. On Linux and macOS it then runs T3 Code as a background service. On Windows the background service is not available, so `t3 up` prints a `t3 serve` command to leave running in a terminal. LAN pairing uses a link or QR code from `t3 pair` or `t3 up --lan`. The page also documents Tailscale and other VPN routes, and a desktop mode that turns the local environment off so that computer only drives work running elsewhere.

The web client is [app.t3.codes](https://app.t3.codes). The README links the iOS app as “T3 Code: Remote Claude & More” and the Android package `com.t3tools.t3code`. This page did not open the store listings for ratings or prices.

That split is the opposite of an agent that operates the screen in front of you. [Can an AI agent use your computer?](/blog/can-an-ai-agent-use-your-computer) is the [computer-use](/glossary/computer-use) guide. T3 Code’s phone is a remote control for a machine that stays on.

One privacy sentence from the FAQ belongs next to the remote claim. Your code and prompts go from your machine to your provider, not to T3. With T3 Connect, traffic rides a Cloudflare tunnel on your machine. The FAQ says the relay sets up the link and does not proxy your HTTP or WebSocket sessions. T3 Code does send product usage events, such as provider, model, and token totals. Prompts and file contents are not in that list. `T3CODE_TELEMETRY_ENABLED=false` turns it off. That is the FAQ’s account, read November 8.

## What permission and approval modes exist?

The permission-modes page lists four modes. You pick one in the message composer, and it applies to that thread. The initial default is Full access. Projects can override the environment default. An administrator can cap the modes on a machine with a managed policy.

| Mode | What the permission-modes page says |
| --- | --- |
| Supervised | Requests approval for commands and file changes. |
| Auto-accept edits | Approves file edits automatically. Other actions can still require approval. |
| Auto | Uses the provider’s automatic review to approve routine actions and ask about others. |
| Full access | Allows commands and edits without approval prompts. |

Those modes are an [approval gate](/glossary/approval-gate) on the thread, and a [human in the loop](/glossary/human-in-the-loop) when the mode still asks. The page is explicit that providers do not all implement the four the same way. Auto uses automatic review on Codex, Claude, Cursor, Grok, and fx. OpenCode and Antigravity, which the page says lack an equivalent, fall back to asking. Claude can still ask in Full access when its own settings disable bypass permissions. Antigravity can still send native approval requests in Full access.

| Provider limit, from the same page | What happens |
| --- | --- |
| Muse Code | Only Supervised and Full access. A thread already set to another mode runs in Supervised. |
| Kiro | Only Supervised and Full access. In Supervised, Kiro also asks you to review a turn’s file changes. |
| fx | No Auto-accept edits and no Full access. A thread already set to either runs in Supervised. |
| Grok | No Auto-accept edits. A thread already set to it runs in Supervised. |
| ACP Registry agents | They run their own tools in their own mode. T3 Code answers their approval requests by the permission mode. |

Approve or reject in the conversation. The page says subagent approval requests appear in the parent conversation with the subagent’s name, so you can answer without switching threads. The v0.1.7 notes call that “child approvals.”

## How is T3 Code different from Claude Code or the Codex app?

Claude Code and the Codex app are harnesses T3 Code can drive. T3 Code is the surface in front of both, plus the other agents in the table above. The FAQ’s “why use T3 Code” answer says the project was inspired by the Codex desktop app, Conductor, Claude Desktop, and Cursor Glass, and that none met its bar. What it lists instead: bring your own subscription, remote with `npx t3 up`, a mobile app, and source you can fork. The README adds that every agent thread writes to its own work, and the homepage says one button can open a GitHub pull request with a generated title, body, and changelog.

The practical difference is whose software is the loop. In Claude Code, you are in Claude Code. In the Codex app, you are in Codex. In T3 Code, the FAQ says those products keep doing the tool calls, and T3 Code is the place you start the thread, pick the permission mode, and attach a phone. Switching agents does not switch you to a new model sold by T3. It switches which installed harness the thread uses.

Two limits from the FAQ are part of that difference. First, T3 Code drives Claude through Anthropic’s Agent SDK. The FAQ says that path drains Claude’s 5-hour limit faster than using Claude Code directly, that weekly limits are unaffected, and that the project has reported it to Anthropic. That is the FAQ’s account of a bug, not a measurement this page re-ran. Second, the FAQ says T3 Code does not support local models. The sentence is blunt: locally runnable models are not capable of meaningful engineering work. A reader who wanted an offline model is outside the product the FAQ describes.

The cost difference is the license. Claude Code and Codex are paid through their own plans, compared in [Claude Code vs Codex pricing](/blog/claude-code-vs-codex-pricing). T3 Code’s FAQ says the control surface itself has no fee. The subscription you bring is still a subscription.
